## Description

Support multiple languages for the UI and for LLM prompts. Allows
non-English-speaking users to operate the platform and extract from
non-English documents.

## Frontend i18n

### Supported Languages (v1)
- English (default)
- Spanish
- French
- German
- Portuguese
- Mandarin (Simplified)

### Implementation
- Use `next-intl` or `react-i18next`
- JSON locale files in `frontend/messages/{lang}.json`
- Detect language from browser
- Language switcher in sidebar footer
- Date/number formatting per locale
- Right-to-left (RTL) layout for Arabic (v2)

### Keys to Translate
- All sidebar labels
- All button labels
- All pane labels
- All status messages
- All empty states
- All error messages
- All form labels in editors

## Backend i18n

### Skill Prompts
- Skill can specify `language` parameter
- System prompt can be templated with `{{ language }}`
- Default: "Respond in English" unless overridden

### Document Language
- Detect document language during pre-processing
- Pass `document_language` to plan node
- Skill can include instruction: "Extract text in its original language"

### API
- `Accept-Language` header respected for error messages
- `GET /api/v1/locales` lists supported languages

## Acceptance Criteria

- [ ] Frontend language switcher
- [ ] All UI strings externalized to JSON
- [ ] `next-intl` or `react-i18next` configured
- [ ] 6 language files included
- [ ] Backend errors respect `Accept-Language`
- [ ] Skill prompt can specify response language
- [ ] Document language detection (basic, via Tesseract lang hint)
- [ ] Unit tests for locale switching
- [ ] Integration test: non-English skill prompt extracts non-English text

## Constraints

- v1: UI translations only. Full multilingual prompts require v2 model
  tuning.
- OCR language packs may require additional Tesseract/Paddle models.
- RTL is v2.
