# BLK-154: CI pipeline broken — references deleted requirements-dev.txt

**ID:** BLK-154
**Source:** REV-003 (independent reviewer)
**Severity:** High
**Category:** Reliability / CI
**Status:** Done
**Assigned to:** Backend
**Estimate:** S

## Problem

The GitHub Actions CI workflow still runs `pip install -r
requirements-dev.txt`, but that file was deleted as part of the uv
migration. The CI job fails at the dependency-install step, so lint,
type check, tests, and coverage do not run on any push or PR.

All "958 tests passing" claims reflect local/manual runs, not automated
CI gate enforcement. Any regression after the uv migration would not be
caught by CI.

## Evidence

- `.github/workflows/ci.yml:25-26` — `pip install -r requirements.txt`
  then `pip install -r requirements-dev.txt`.
- `requirements-dev.txt` does not exist (deleted during uv migration).
- `requirements.txt` is now an autogenerated uv export.
- The uv migration's own acceptance criterion ("No pip install commands
  in any scripts or docs") was marked complete without updating ci.yml.

## Resolution

1. Update `.github/workflows/ci.yml` backend job:
   - Install uv: `pip install uv` or use astral-sh/setup-uv action.
   - Replace `pip install` with `uv sync --all-extras`.
   - Replace `ruff check` with `uv run ruff check src/`.
   - Replace `mypy` with `uv run mypy src/ --ignore-missing-imports`.
   - Replace `pytest` with `uv run pytest src/tests/ -v --tb=short`.
   - Replace coverage with `uv run pytest src/tests/ --cov=src
     --cov-report=term-missing --cov-fail-under=80`.
2. Verify CI goes green on a real PR before closing.

## Tests

- Push a PR after fix → backend CI job completes through coverage step.
