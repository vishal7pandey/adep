## The Problem

The current Skill Editor (`SkillEditor.tsx`) is a 6-section form
that exposes every internal concept at once: probe order, invariants,
failure actions, semantic checks. These are developer/engineering
concepts, not user-facing concepts. The form is intimidating and
hard to use.

## Industry Research

I checked how industry leaders handle this:

### OpenAI GPT Builder
- **Two modes**: "Create" (conversational, beginner) and "Configure"
  (manual, advanced)
- Beginners describe what they want in natural language
- Experts switch to Configure for raw system prompt + toggles
- **Key**: simple path is always one click away

### Flowise
- **Three tiers**: Assistant (simplest) → Chatflow → Agentflow
- Progressive disclosure — users start simple and graduate
- **Key**: beginners never see advanced concepts

### CrewAI
- Skills are just `SKILL.md` files: name, description, instructions
- No probe order, invariants, or failure actions in the UI
- Those are code-level concerns, not UI-level
- **Key**: skills are instructions + metadata, not engineering config

### Langflow
- Visual canvas with drag-and-drop tool connections
- Tool descriptions are editable, human-readable
- **Key**: visual composition over form-filling

## Common Pattern

**Nobody exposes probe order, invariants, and failure actions as
top-level form sections.** These are always either:
1. Auto-generated from the document type
2. Hidden behind an "Advanced" toggle
3. Generated by AI

## The Fix: BLK-101

Redesign the Skill Editor with **two modes**:

### Simple Mode (default)

4 concepts only:
1. **Name + Description** — what is this skill for?
2. **Document Type** — dropdown (Invoice, Receipt, Contract, etc.)
   - Selecting a type auto-fills prompt, tools, invariants, etc.
   - "Custom" option for from-scratch
3. **System Prompt** — textarea, auto-filled from document type
   - "Auto-generate" button (placeholder for BLK-068 AI Skill
     Composer in Phase 5)
4. **Tools** — toggle checkboxes with human-readable labels
   - "OCR (text extraction)" not "paddle_ocr"
   - "Layout Detection" not "detect_layout"
5. **Validation** — simple checkboxes
   - "Verify math (sums, totals)"
   - "Verify dates (format, range)"
   - "AI verification (LLM semantic check)"

### Advanced Mode (collapsible, hidden by default)

Shows the current 4 sections with better labels:
- "Probe Order Strategy" → "Extraction Steps"
- "Invariants Verification Rules" → "Validation Rules"
- "Failure Action Actions" → "Fallback Behavior"
- "Pragmatic Semantic Checks" → "AI Verification"

### Document Type Presets

When user selects "Invoice" from the dropdown:
- System prompt auto-filled with invoice instructions
- Tools auto-selected (OCR, layout, crop, table reader, validation)
- Invariants auto-filled (subtotal + tax = total)
- Failure actions auto-filled (low confidence → VLM, OCR error → deskew)
- Probe order auto-filled (scan → table → verify)

User can then tweak anything. This replaces the empty-form problem.

### Toggle Between Modes

```
[Simple | Advanced]
```

A toggle switch at the top right. Default is Simple. Switching to
Advanced expands the form with the additional sections. All data
preserved when switching.
